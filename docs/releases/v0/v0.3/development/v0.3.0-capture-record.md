## Causes per card

The plan's three suspected causes were tested against these lines.

1. **Platinum and Business Platinum: the activity page is read while the Rewards content is still on screen (confirmed, new cause).** Every activity line with `trackers=2` also has `activity=true`, but no activity page holds an activity link (both Platinum-type view-all/activity captures: activity link absent). Amex opens the activity page without loading a new document: the address changes, the page script restarts on that change, and the old Rewards content stays rendered for several seconds. The restarted script classifies the page by its address (`activity`), sees 2 steady trackers, and posts them after 2 s. In refresh 1 the second card's activity page had rendered in time (`trackers=12 listed=150`, the list capped by the count limit); in refresh 2 both cards posted Rewards content. The plan's cause 2 (posting from Rewards before the activity link renders) is not what happened: the link was found and followed every time.
2. **Hilton Surpass and Gold Delta SkyMiles: their full list lives on view-all, which the read never opens (confirmed, plan cause 1).** Their Rewards pages show 2 trackers and 4 benefits; their view-all pages show the same 2 trackers and 20 and 24 benefits.
3. **The card switch restarts the page script (confirmed mechanism, plan cause 3).** Cards 3 and 4 are reached by an in-place switch, yet their lines say `switched=false`: the switch changes the address, the script restarts, and the new run neither knows a switch happened nor compares trackers before and after. Here the reads still landed on the right card's 2 trackers, but nothing guards the empty-tracker case the plan describes.
4. **A short read erases the stored set (confirmed, plan defect 4).** Business Platinum went from its full set after refresh 1 to 2 items after refresh 2, because `applyCardBenefits` replaces a card's whole set with whatever the read returned.

Not every page reached the bottom before posting (`bottom=false` on 4 of 8 pages). Timing: each card took 7 to 16 s; the whole read took 43 to 46 s, well inside the 120 s budget.

## Phase 3 go/no-go

**GO.** View-all exists for Hilton Surpass and Gold Delta SkyMiles, shows only the selected card, and holds that card's trackers. Phase 3 reads view-all through the page's own link (decision 3.1 option B).

## Consequences for Phase 2

- An activity page is ready only when it no longer shows an activity link and its list count is steady; a page whose address changed but whose content is still the Rewards page is not ready.
- A switch must survive the script restart: the app, which already knows the target card, should treat the first page after a switch as switched, so the switch invariant holds across the address change.
- Ready rules should require the bottom of the page for every kind, as the plan's default proposes.
