# v0.3.1 Phase 3: Alerts and Freshness

## Changes

Yellow warning counts and top-of-card alerts support individual persisted acknowledgement. Alert identity retains the original source row even after safe tracker/list merging. Only a successful relevant section read advances its alert generation. Room version 4 preserves existing data and adds an atomic read counter; DataStore outcomes bind to the counter and read time, preserving explicit unknown/unread-list status after missing outcomes. Failed saves retain state and show visible polite feedback. Manual validation identifies invalid fields and rejects expensive exponent syntax before decimal conversion.

## Verification

Final focused gate: 63 JVM cases and 3 Android fixtures, zero failures/errors/skips, command exit 0. Tests include the real Room/DataStore/SyncManager path, migration data preservation, source rollover/removal, failed/cancelled reads, restart, simultaneous acknowledgement/refresh/sort, unchanged reminder records, displayed failed-save feedback, and actual Android alert controls. Six current synthetic captures were inspected and retained with source hashes in v0.3.1-phase-3-verification.json.
