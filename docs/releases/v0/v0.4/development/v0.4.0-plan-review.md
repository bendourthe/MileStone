## Design Interview

**Settled**: Top search icon, global programs/cards/benefits scope, program grouping, v0.4 target, and preservation of current sign-ins/data. The top icon replaces the earlier bottom-tab idea.

**Q1. Corpus**

Should global search include only added programs and their stored data, or also unadded catalog programs? The first scope stays focused on the owner's information. Including unadded programs needs visibly distinct discovery results and an Add program action.

> **Recommended**: Added programs and their stored cards/benefits only. Keep program discovery in the existing Add program screen.

**Q2. Contextual Queries**

Should `Delta lounge` match a lounge benefit when Delta is found in its parent card/program name? Entity-only matching is predictable but misses that contextual query. Parent-aware matching can find it while requiring one token in the benefit itself to avoid returning every descendant for a parent-only query.

> **Recommended**: Match across item fields plus parent names, with at least one token matching the item itself.

Both branches are resolved. The owner answered the corpus question with `Added programs and stored data only (Recommended)`, then replied `Use recommendations` to confirm both choices and the four-phase breakdown. The final plan records both decisions and corresponding matching examples. No branch is parked. Planning approval and implementation authority remain separate.
