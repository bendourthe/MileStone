# CI Runtime Proposal

## Status

DRAFT, NOT APPLIED. The exact [workflow patch](v0.4.0-ci-runtime-proposal.patch) passes `git apply --check` against the current working workflow. It has not run on Linux or GitHub, and no remote validation, settings change, commit or publication is authorized by this artifact. The owner decision remains pending.

## Behavior

Keep the existing standard Ubuntu 24.04 job, pinned setup actions, contents-read-only permission, PR-only trigger, 75-minute job deadline, seven-day reports and stable CI result. After the existing full profile passes, provision one API 36 x86_64 Android virtual device using the installed SDK tools, scoped to the ephemeral runner directory. Grant only the runner account access to its KVM device. Boot without a visible window or saved snapshot, with bounded readiness checks. Invoke the unchanged native platform profile with emulator-5554, which independently verifies that it is an emulator. Stop that assigned emulator and always retain reports. No extra action, persistent runner, issuer credential or owner capture is added.

## Cost and Evidence

The repository is PUBLIC. Standard hosted runner compute is free for public repositories under [GitHub policy](https://docs.github.com/en/actions/how-tos/write-workflows/choose-where-workflows-run/choose-the-runner-for-a-job). The proposal adds SDK provisioning, boot and the real suite duration to pre-merge validation; it does not claim all storage or services are free. [GitHub documents Android hardware acceleration on standard Linux runners](https://github.blog/changelog/2024-04-02-github-actions-hardware-accelerated-android-virtualization-now-available/). [Android documents AVD creation](https://developer.android.com/tools/avdmanager), [headless emulator startup](https://developer.android.com/studio/run/emulator-commandline), and [current acceleration modes](https://developer.android.com/studio/run/emulator-acceleration). The proposal uses swiftshader; the older swiftshader_indirect mode is deprecated.

Local Windows evidence remains separate: 68 emulator cases and the unchanged p95 requirement passed on the qualified APK. The proposed hosted boot/environment and actual merge-result runtime require genuine remote authority and the actual PR result. A missing KVM device, boot failure or failed test remains a failed job; the proposal does not skip tests or weaken the latency requirement.
