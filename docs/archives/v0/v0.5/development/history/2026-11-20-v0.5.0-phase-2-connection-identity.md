# v0.5.0 Phase 2 | Connection and Identity Foundation

- **Date**: 2026-11-20
- **Plan**: [v0.5.0 Chase Personal and Business Benefits](../../plans/v0.5.0-chase-benefits.md), Phase 2 (T004-T006)
- **Branch**: `feat/v0.5.0-chase-benefits`, on top of the Phase 1 commit `a665be7`
- **Decision**: [ADR-0009](../../../../../decisions/0009-chase-benefits.md)

## Summary

Cards now have a local identity independent of their last digits, and an issuer can have several independent sign-ins (connections) whose card coverage is tracked separately. Every existing Amex card keeps its last digits as its card id, so benefits, reminders, benefit keys, display preferences and Search keys are unchanged byte for byte. Chase's first sign-in reuses the existing profile, saved sign-in and encryption associated data.

## Work

- **T004 (storage)**:
  - `CardKey(programId, cardId)`: legacy 4-5 digit ids or opaque `c_` + 16 hex local ids; `displayDigits` shows only legacy digits.
  - `Card` gains `cardId` (defaults to `lastDigits`) and an effective `segment`.
  - Room version 5 with a manual migration that rebuilds `cards`, `benefits` and `benefit_reminders` with `cardId` (copied from `lastDigits`) and adds `issuer_connections` and `card_coverage`.
  - `applyConnectionInventory`: matches cards by keyed binding hash only, within the connection and then across connections when exactly one card is bound; a complete non-empty inventory removes only that connection's coverage and deletes only unreachable cards; partial, stale, duplicate-binding and unknown inventories change nothing.
  - Segment rule: Personal when any Personal connection reaches the card, Business when only Business ones do, with a per-card owner override.
  - The legacy last-digits card list prunes only cards no connection reaches.
- **T005 (sessions)**: `ConnectionSessions` provides the legacy connection (id = program id: `program_<id>` profile, `<id>` saved sign-in), adds isolated sign-ins `<program>_<n>` (at most 4, refused without MULTI_PROFILE), signs out one additional sign-in without touching others, and keeps other sign-ins' cards when the legacy sign-in signs out. Startup cleanup keeps additional sign-in profiles. Chase Rewards balance reading is unchanged (legacy profile only), so linked observations are not double-counted.
- **Display**: key uses moved to `cardId`; "card ending" texts use `displayDigits`, so an opaque id is never shown or searchable.

## Plan delta

- **Disposition**: Incomplete, non-blocking.
- **Evidence**: T004 asks to preserve "manual welcome values and alert acknowledgements"; these live in display preferences keyed by the card key, and are preserved because legacy card ids equal the old last digits (no preference migration needed). Showing the stored ending of connection cards (not just legacy keys) needs the card model, not the key, in tile, page and Search UI models.
- **Consequence**: Phase 4 must pass `Card.lastDigits` into the tile, page and Search display models for connection cards. Phase 3 must produce `SourceCard` values with a per-install keyed binding hash (no raw selector id persisted) and drive reads through the connection's profile. No plan text changed.
