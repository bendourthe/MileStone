## Presentation and Local State Decisions

- Display categories are Welcome bonus, Credits, Spend trackers, Other. These are separate from BenefitSection, whose values continue to control issuer parsing and section-scoped writes. Completed entries stay in their meaningful category; an unclassifiable completed entry remains visible in Other.
- Default ordering is case-insensitive alphabetical with a stable-key tie break. Completed-last is an explicit per-card option. Other starts collapsed. Each card stores its own sort and category choices; navigation or restart must not reset them.
- Duplicate suppression operates on copied presentation rows only. Normalize case, whitespace, punctuation, currency amounts, and generic credit/benefit descriptors, but preserve period words. A listed entry can enrich one unambiguous matching tracker on the same card with its description/enrollment. Different periods, multiple possible trackers, empty normalized titles, or conflicting enrollment statuses remain visible. Raw issuer rows are never deleted by this display operation.
- Bundled artwork will identify known public card products by product name, never by account identifiers: Business Platinum, Platinum, Hilton Surpass, and Delta Gold. Require distinct matching images and a generic offline fallback; a generic placeholder alone does not satisfy the four-product artwork requirement.
- Alert identity includes its kind and benefit identity, and acknowledgement records the successful read generation for the relevant source section. Acknowledgement must not clear enrollment or reminder records. A later successful relevant read can reintroduce the still-applicable alert; another card's read or a failed/cancelled read cannot reset it. The per-list generation/outcome must be persisted reliably before list-specific freshness is presented as verified.
- The local welcome-bonus setup stores user-entered spend, target, optional deadline, and reward label separately from account balances and issuer rows. Validation rejects negative spend, nonpositive targets, excessive/control-character labels, and malformed persisted values. This does not restore manual account balance entry.
- Reuse the existing DataStore file through a dedicated display-settings interface. Each write changes only its own preference keys, so unrelated settings and other cards are preserved. Missing settings use visible defaults; malformed optional manual setup is ignored without erasing issuer data.
- Keep the current permission banner and notification reminder behavior. The new alert acknowledgement controls are in-app actions and do not dismiss or delete system reminders implicitly.
