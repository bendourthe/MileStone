## Plan delta

**Disposition: Incomplete (non-blocking).**

Evidence: the plan's 2.3 fixture for the lazy Rewards page reproduced only a late lower section; the live cause found in Phase 1 is the activity link changing the address in place while the Rewards content stays. The lazy fixture's activity link was made in-place, which is what makes the reproduction above fail on the Phase 1 script. The plan's 2.3 also asked for "a JVM or Robolectric test for the source"; a Robolectric WebView does not run page scripts and the source returns `UNSUPPORTED` without WebView message features, so the deadline rules moved into the pure `BenefitsReadBudget` and the test drives that class with the source's call pattern.

Consequence for the remaining phases: Phase 3's view-all page uses the same handoff note (`listedBefore`) and the `viewAll` marker already in the script; its 3.1 decision picks option (B), pressing the page's own link, as the capture record recommends. Phase 4's live check reads the new cut lines (`benefits cut:`) if any appear.

## Deviations

- The cut order is sticky (once a second page is cut, later cards read their first page only), a refinement written into the ADR after the budget test showed the non-sticky rule could give a later card a second page and then leave the last card unread.
- The capture record's expected-count table now uses the app's own section rules (from a count-only probe of the private captures), replacing the heading counts.
