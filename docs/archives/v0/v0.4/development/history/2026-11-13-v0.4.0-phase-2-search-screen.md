# v0.4.0 Phase 2 - Search Screen

## Scope and Changes

Implemented T004-T007 under the owner's existing reversible-local search authority. Rewards, Benefits institution/card lists and the opened card page expose the same accessible 48 dp Search action. Search is one navigation-entry-scoped route, with no bottom tab, local read states, grouped lazy results, exact counts, description/alternate-title context, completion and existing freshness text. Header actions remain present. Selection routing remains Phase 3 and this intermediate APK is not delivered to the owner.

Query, first-focus flag and results position belong to the entry's in-memory ViewModel. They are not passed through routes, SavedStateHandle, rememberSaveable or storage. Clear retains focus; fresh navigation starts blank. Visible Back closes directly; Android system Back dismisses the keyboard first. Actual Activity recreation retained the same model and query, and did not request focus again.

## Verification

The final gate exited 0: 51 affected JVM tests, 9 emulator tests, lintDebug and assembleDebug. All test cases passed with no errors or skips. Android instrumentation explicitly targeted emulator-5554, at 720x1280 pixels and density 320 (360 dp wide), never the owner's phone. Detailed counts, lint totals, tested source/report/APK hashes and synthetic screenshot hashes are in v0.4.0-phase-2-verification.json.

The built app navigation was exercised using injected synthetic Room repositories with no issuer/sign-in callbacks. Observed grouped contextual and description-only results, completion/period context, exact result counts, Clear, empty/start states, delayed reads, generic errors and local retry. Entering and closing Search returned to Benefits institutions, its card list and an opened card. A real keyboard test confirmed the first system Back leaves Search open after dismissing IME and the second returns to Rewards. Configuration-change and fresh-model checks cover memory ownership; full process-restart privacy and result-page scroll restoration remain in the later acceptance gate.

Early test runs exposed fixture mistakes: hidden tile text was queried instead of its deliberate combined accessibility label, Back was expected to bypass keyboard dismissal, and a large-font result was checked behind the keyboard. The fixture now uses actual semantics, separates visible/system Back, controls IME state and wraps content in the production AuroraBackground. Synthetic visual review then found real 200 percent layout defects: the extra Rewards wordmark wrapped over the centered logo, and the long outlined-field label crossed the header. Large font now retains the centered logo with its accessible name, and the field uses a short label while the blank state retains the full prompt. The final 9-case run includes non-overlap assertions and both corrected screenshots were visually inspected. No failed assertion was skipped.
