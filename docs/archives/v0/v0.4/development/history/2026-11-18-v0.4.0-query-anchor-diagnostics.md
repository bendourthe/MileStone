# Query Anchor Diagnostics

## Scope

This local diagnostic adds the existing query-start, state-ready and visible-draw timestamps to the synthetic Search metrics, naming Android elapsedRealtimeNanos as the clock. An opt-in offline validator checks their identity, order and agreement with measured latency. It changes no production search, result content, sample sequence, corpus, navigation, privacy boundary or 200 ms p95 limit. It is not a demonstrated performance correction.

## Failure Identity

[PR 17 run 44183989525](https://github.com/bendourthe/MileStone/actions/runs/44183989525) failed the optimized, non-debuggable benchmark at p95 230.097183 ms. Its artifact is bound to target com.bendourthe.milestone.benchmark and the query-to-visible-v1 contract. Seven of thirty samples exceeded 200 ms. All seven have zero recorded garbage collections. Their recorded result-readiness intervals are 112.583941 to 173.896512 ms; main-thread CPU intervals are 17.733225 to 39.310523 ms. The phase rows match their measured query families and counts after the three warmups. These facts motivate investigating worker and scheduling delay but do not prove its cause.

[PR 18 run 44370534037](https://github.com/bendourthe/MileStone/actions/runs/44370534037) instead failed the older debug SearchLatencyTest at p95 220.493658 ms. Its metrics have no optimized-target, debuggable, run UUID or scenario-contract identity fields, and its platform result contains only the debug runtime group. Those timings must not be treated as the optimized release failure. The release worktree already excludes this optional debug timing test from functional runtime and retains the optimized performance gate separately. This diagnostic does not introduce that existing split or use it to waive optimized qualification.

The unchanged optimized workload, all functional gates, security, source packaging and required green integration remain mandatory before release.

Other dirty tracker, plan and historical-reconciliation files stay outside the package. The prior feb0d8d one-push grant is consumed. A hosted diagnostic could expose the anchors on the controlled runner while retaining the 200 ms gate.
