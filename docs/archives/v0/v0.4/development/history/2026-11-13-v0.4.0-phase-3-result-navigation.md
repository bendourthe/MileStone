# v0.4.0 Phase 3 - Result Navigation

## Scope and Changes

Implemented T008-T010 under the owner's reversible-local search authority. Typed selections open the exact Rewards program or Benefits card. A benefit visit retains its opaque source revision in the Search navigation entry, validates a fresh transactional read, validates the exact source behind the rendered card page, temporarily expands only its category, waits for the stable row layout, revalidates, scrolls and identifies the canonical row with an outline, a Search result label and an accessibility announcement. No saved category, sort, welcome-bonus, acknowledgement, issuer or sign-in data is rewritten by search.

The Search entry stays below its result destination and retains its query and results position. A single live source subscription preserves revision invalidation during the visit. Selection locks synchronously, shows progress, cancels with the entry, and cannot navigate after a query change or overwrite a visit through a repeated tap. Removed targets keep valid navigation and report unavailable; occurrence-key reuse reports Results changed. Select the item again. Late reads never navigate to a different item. The card page exposes the shared snackbar host for a subsequent invalidation notice.

## Root Causes and Corrections

The device tests exposed a continuation resuming on a worker thread after a local read under the Compose test interceptor. The first error was Method setCurrentState must be called on the main thread; the later lifecycle failure during shutdown obscured it. Navigation and reveal scrolling now explicitly use Android Main, preserving the surrounding job/frame clock. Multi-visit and removal tests pass without suppressing the error.

Origin-return testing then measured an exact 160-pixel drift at density 320. Hiding the 80 dp bottom bar enlarged the outgoing list before disposal and clamped an end-of-list anchor. Stable per-destination insets fix that cause. Existing list state now resets only on actual sort/completed-order changes, rather than on every composition return. Rewards and opened-card positions are equal before and after Search, while normal preference changes retain their reset behavior.

Fixture corrections use the real explicit clear-card API because an empty issuer read intentionally preserves cards. Tests wait for merged actionable controls and scroll lazy results into view after dismissing IME. No behavioral assertion was removed or skipped. A canceled duplicate invocation cleared its prior reports; no evidence from that cleared report is reused. The final complete 20-case XML is retained in the release evidence tree.
