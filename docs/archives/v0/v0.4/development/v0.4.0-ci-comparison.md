## Prerequisites and Security

Profiles never install dependencies or fetch a tool. Full needs scripts/requirements-validation.txt (Playwright 1.64.0) and its Chromium runtime. CI provisions those in a local virtual environment, reuses pinned Java/Android/Gradle actions and preloads the exact approved Gitleaks image digest. Local Gitleaks discovery uses PATH or --gitleaks-executable; otherwise it requires the already cached Docker image zricethezav/gitleaks@sha256:2bcceac45179b3a91bff11a824d0fb952585b429e54fc928728b1d4d5c3e5176. Docker execution uses --pull=never and --network=none. Only .gitleaks.toml is mounted read-only and the SARIF directory is mounted writable; the worktree and ignored captures are never mounted. Missing prerequisites fail with an explicit limitation, rather than becoming a successful fake scan.

Security uses the existing Gitleaks defaults plus the repository's exact allowlist, an in-memory synthetic positive control, committed origin/develop..HEAD patches, the complete candidate diff and nonignored new public text. Private captures, environment/key files, machine-local inputs and database copies/companions are excluded before reads. The security payload has its own recorded hash. The profile input fingerprint separately hashes the selected public code/test/build/schema/CI/helper/living-handbook inputs. Release evidence, histories, archives and release-scoped verification receipts do not invalidate unchanged code gates or create self-reference churn. App/test/CI/helper/handbook actual inputs remain in scope; ignored private inputs remain owned by their independent private-fixture gate. Committing identical input bytes does not invalidate a code receipt merely by changing HEAD.

Reports use relative artifact paths, sanitized command output and selected metadata, never a complete environment dump. A single subprocess launch site hides Windows children, preserves compatible flags and terminates its owned process tree on timeout. Failed commands stop their group; independent groups continue unless a blocking private-input/emulator boundary fails. Android XML is counted only from the selected successful task's outputs (including Gradle-validated unchanged outputs), or fresh partial XML after a failed task. Old XML cannot turn an early failure into a green test count. This reuse scope is recorded explicitly; it is not labeled a new test execution.

## Failure Recovery

A failed profile remains failed even if a later group passes. Fix/reproduce the specific local failure, retain unchanged successful scopes only with matching source fingerprints and limits, then rerun affected gates. A missing tool or remote-only difference is evidence of missing coverage, not a reason to rerun blindly. Required final CI still validates the current merge candidate. A dirty source candidate or failed archive integrity check stops source packaging; this helper never tags or publishes. Owner-approved runtime configuration and applied/read-back protections resolve QG-1/QG-2. Actual hosted execution and the protected merge-result success remain T020; fresh affected local validation remains T019.
